# Browser tests

Real-browser (Puppeteer + system Chrome) end-to-end tests. These exist because PHPUnit's
HTTP-level feature tests cannot catch JS runtime bugs - the exact class of bug that slipped
through earlier: `axios is not defined` and a broken poll-dedup key were both invisible to
`php artisan test` but broke real usage completely.

## Prerequisites

- The app's dev server running and reachable at `BROWSER_TEST_BASE_URL` (default `http://localhost:8000`).
  Start it with worker concurrency so multi-user scenarios (two logged-in sessions polling
  at once) don't serialize against each other:
  ```
  PHP_CLI_SERVER_WORKERS=4 php artisan serve
  ```
- The database migrated and seeded once (`php artisan migrate && php artisan db:seed`): the feature-flag and
  archive tests need the admin seed data (without it "feature flags load" times out).
- A mailer that works, or `MAIL_MAILER=log` for the server (the archive test e-mails the archive; a mail host that
  does not resolve makes "the archive request is accepted" time out).
- Google Chrome installed at `CHROME_PATH` (default `/usr/bin/google-chrome`).
- `npm install` (installs `puppeteer-core`, which drives the system Chrome above - no bundled
  Chromium download).

## Running

```
npm run test:browser            # all *.test.js files in this directory
npm run test:browser -- phase1  # only files whose name matches "phase1"
```

The runner (`run.js`) first seeds three fixed, verified users via
`php artisan test:seed-browser-users` (see `app/Console/Commands/SeedBrowserTestUsers.php`,
guarded against running in production), then loads and executes every `*.test.js` file.

## Writing a new test file

```js
import { test, assert } from './support/test.js';
import { loginAs, closeSession, USERS, absoluteUrl } from './support/session.js';

test('describe the behavior', async () => {
    const alice = await loginAs(USERS.alice);
    // ... drive alice.page like a real browser ...
    assert(alice.errors.length === 0, `unexpected JS errors: ${JSON.stringify(alice.errors)}`);
    await closeSession(alice);
});
```

- `loginAs(email)` opens an isolated browser context (its own cookie jar - a real separate
  session, not a shared tab) and returns `{ page, errors, context }`. `errors` accumulates
  every `pageerror` / `console.error` / failed request for that page's lifetime - always
  assert it's empty at the end of a test; that's what would have caught the axios bug
  automatically.
- Routes generated by Laravel's `route()` helper in this app are **absolute** URLs (APP_URL-based).
  Use `absoluteUrl(href)` when navigating to an href scraped from the DOM - don't
  string-concatenate `BASE_URL` with it.
- A failing `assert()` throws; `run.js` closes every open session after each test
  automatically (pass or fail), so one test's failure can't leak browser state into the next.
- Scope click selectors to the actual form/element you mean - `button[type="submit"]` alone
  will happily match the shared layout's "Log out" button if it appears earlier in the DOM.

## What's covered so far

`phase1-2.test.js` - login, profile, contact request/accept, 1:1 chat (including an explicit
regression check that polling doesn't re-append the whole history), presence heartbeat, and
group creation/messaging.

`message-actions.test.js` - react, reply, star/pin, delete-for-me, forward, mute/archive.

`media.test.js` - image/document/voice-note upload+render, One View consume-once lifecycle.

`calls.test.js` - real two-browser voice and video calls: outgoing/incoming UI, accept, actual
WebRTC negotiation (both sides receive the other's live audio/video track from the fake media
device), ending a call and it appearing in both parties' call history, declining a call, and the
busy/409 path when a third party calls someone who's already ringing.

`meetings.test.js` - scheduling a meeting with a waiting room (host admits from the waiting
room, real mesh WebRTC connects), a guest joining/creating an instant meeting with no account,
the Meetings page's merged All/History tabs + Calendar as its own nav-reachable page, and
Calendar's month/week/day view switching, day-detail popover, and dragging a month-view chip to
reschedule the underlying meeting.

`calendar-resize.test.js` - adding a personal calendar entry (no linked meeting), dragging its
Week/Day resize handle to change duration only, and deleting it.

`navigation.test.js` - the merged 4-item nav (Chat/Groups tabs, no separate Groups icon) and the
nav-wide unread/contact-request badge appearing on new activity and clearing once read.

`admin.test.js` - admin dashboard stats + non-admin nav visibility, Users search/suspend/
reactivate, real-vs-load-test account tabs, role creation/permission grant/delete, branding/
feature-flag updates with audit-log entries, manual archive build+download, PWA manifest/service-
worker reachability, the header's real logo + working install button.

`broadcast-lists.test.js` - creating a broadcast list and sending a message delivers it as
separate 1:1 chats to each recipient.

`communities.test.js` - creating a community auto-creates its Announcements group; attaching an
owned group makes its members see community announcements; removing ("detach") an attached
group and deleting the whole community.

`chat-export.test.js` - exporting a chat from the header kebab menu downloads a real zip with a
transcript inside.

`settings.test.js` - the Settings page saving/prefilling every profile/preference/notification/
chat-default field, change-password and deactivate-account error handling, and the push
notification devices list/revoke page.

`push-notifications.test.js` - a real Web Push subscription is created once notification
permission is granted (runs on the browser's default, non-incognito context - Chrome disables
the real Push API in incognito, which is what `loginAs()` uses everywhere else).

`two-factor.test.js` - enabling 2FA requires a real TOTP code (computed via a hand-rolled RFC
6238 generator, no new dependency), logging back in requires that code too, and checking
"remember this device" on the challenge skips it on the next login from the same browser.

`passkeys.test.js` - registering a passkey from Settings (via Chrome's real CDP virtual
authenticator, no hand-rolled crypto) and logging back in with the passkey alone, no password.

`sso.test.js` - the login page's "Continue with Google" button redirects to a real Google OAuth
authorize URL (the actual account-creation/linking/2FA-interaction logic is covered by PHPUnit's
`SsoAuthenticationTest` via Socialite's fake, since a real OAuth consent flow needs a real Google
account this environment doesn't have).

`mobile-nav-overlap.test.js` - the fixed mobile bottom nav bar never overlaps the last button on
a long settings page at a real small-phone (375×667) viewport, confirmed via a `scrollIntoView`
repro that reliably reproduced the bug before the fix.

### A note on running everything at once

Each file passes cleanly on its own (`npm run test:browser -- calls`, `-- media`, etc.). On a
memory-constrained machine, running every file back-to-back - especially `calls.test.js`, which
holds real audio/video streams open across several Chrome tabs at once - can exhaust system
memory/swap and crash the shared Chrome instance, cascading into unrelated later failures
("Connection closed"). That's an environment/resource limit, not a test bug. If the full run
crashes, run files individually (or in smaller groups) instead.

Two known, documented flakes (not caused by any of the above): `admin.test.js`'s branding/
feature-flag test occasionally fails on `[data-tab="features"]` not being found, and
`phase1-2.test.js`'s "message received exactly once" test is occasionally flaky under load -
both pass reliably when re-run in isolation. See `BACKLOG.md`'s "Known rough edges" section.
