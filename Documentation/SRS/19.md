# Software Requirements Specification (SRS)

# Chapter 19 - Guest Mode & Public Access

---

# Module Overview

The Guest Mode & Public Access module allows users to join meetings without creating an account while maintaining platform security and host control.

Guest Mode is intended for quick collaboration and temporary access. Guests shall have restricted permissions and limited session duration.

The module integrates with:

* Meeting Engine
* Authentication Engine
* Notification Engine
* Security Engine
* Analytics Engine
* Admin Panel

---

# FR-316 - Guest Meeting Access

## Purpose

Allow non-registered users to join meetings using a shared invitation link.

---

## Actor

Guest User

---

## Priority

Critical

---

## Workflow

1. Guest opens the meeting link.
2. System validates the meeting.
3. Guest enters a display name.
4. Guest requests to join.
5. Host admits the guest (if Waiting Room is enabled).
6. Guest joins the meeting.

---

## Acceptance Criteria

* Guest joins successfully after validation.
* Guest appears in the participant list with a Guest badge.

---

# FR-317 - Guest Session Duration

## Purpose

Limit anonymous access.

---

## Default Duration

15 Minutes

---

## Administrator Configurable

* 5 Minutes
* 10 Minutes
* 15 Minutes
* 30 Minutes
* 60 Minutes
* Unlimited (Disabled by Default)

---

## Business Rules

Guests shall be notified before their session expires.

---

# FR-318 - Guest Permissions

## Default Permissions

Guests may:

* Join Meeting
* Enable/Disable Microphone
* Enable/Disable Camera
* View Shared Screen
* Participate in Meeting Chat (Configurable)
* View Whiteboard (Configurable)

---

## Guests Shall Not

* Schedule Meetings
* Access Private Chats
* Create Groups
* View User Profiles
* Change Meeting Settings
* Access Admin Features
* View Meeting History
* Download Restricted Files

---

# FR-319 - Guest Identity

## Purpose

Display guest identity without requiring registration.

---

## Guest Information

* Display Name
* Guest Badge
* Join Time
* Device Information (Internal)
* IP Address (Audit Only)

---

## Business Rules

Display names do not need to be unique.

---

# FR-320 - Waiting Room for Guests

## Features

Host may:

* Admit Guest
* Reject Guest
* Admit All Guests
* Remove Guest

---

## Business Rules

Host receives a notification whenever a guest requests access.

---

# FR-321 - Guest Meeting Link

## Purpose

Generate secure invitation links.

---

## Requirements

Each guest link shall contain:

* Meeting Identifier
* Secure Token
* Expiration Validation
* Optional Password Requirement

---

## Business Rules

Expired or invalid links shall be rejected.

---

# FR-324 - Guest Whiteboard Access

* Draw with Permission

# FR-325 - Guest File Sharing

## Default

# FR-326 - Guest Security

## Requirements

* Secure Join Token
* HTTPS Required
* Authorization Validation
* Meeting Membership Validation
* Activity Logging
* Rate Limiting

---

## Business Rules

Guests shall only access the meeting for which they possess a valid invitation.

---

# FR-327 - Guest Session Expiry

## Workflow

1. Session reaches configured duration.
2. Warning displayed before expiry.
3. Session expires.
4. Guest removed from meeting.
5. Host notified (Optional).

---

## Business Rules

Rejoining requires a valid invitation and host approval if applicable.

# Chapter Summary

The Guest Mode & Public Access module provides secure, temporary access to meetings without requiring user registration. It includes configurable session durations, waiting rooms, restricted permissions, secure invitation links, host approval workflows, analytics, and administrative controls. The architecture balances ease of access with platform security while supporting your requirement for **15-minute free guest meetings** and future extensibility.
