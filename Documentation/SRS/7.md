# Software Requirements Specification (SRS)

# Chapter 7 - Voice Call Engine

---

# Module Overview

The Voice Call Engine provides secure, high-quality one-to-one voice communication using WebRTC. The module is designed for Laravel running on cPanel hosting by using a polling-based signaling architecture while keeping the system ready for future migration to WebSockets or a dedicated signaling service.

---

# FR-086 - Start Voice Call

## Purpose

Allow a user to initiate a voice call with another registered user.

---

## Actor

Authenticated User

---

## Priority

Critical

---

## Preconditions

* Caller is authenticated.
* Recipient account is active.
* Recipient has not blocked the caller.
* Recipient is available or allows incoming calls.

---

## Workflow

1. User opens a conversation.
2. Clicks the **Voice Call** button.
3. Browser requests microphone permission.
4. WebRTC peer connection is initialized.
5. SDP Offer is generated.
6. Offer is sent to the Laravel signaling API.
7. Recipient receives an incoming call notification.
8. Recipient accepts or rejects the call.

---

## Database Tables

* calls
* call_participants
* signaling_messages
* activity_logs

---

## Acceptance Criteria

* Call request reaches the recipient.
* Ringing starts.
* Connection is established after acceptance.

---

# FR-087 - Incoming Call

## Purpose

Notify the recipient of an incoming voice call.

---

## Features

* Caller Name
* Caller Avatar
* Ringing Screen
* Accept
* Reject
* Mute Ringtone

---

## Timeout

Incoming call timeout shall be configurable.

Default: **30 seconds**

---

## Acceptance Criteria

* Recipient receives call notification.
* Call expires automatically if unanswered.

---

# FR-088 - Accept Call

## Workflow

1. User clicks **Accept**.
2. Browser requests microphone access if required.
3. SDP Answer is generated.
4. Answer is sent to Laravel.
5. ICE candidate exchange completes.
6. Voice communication begins.

---

## Acceptance Criteria

* Both users hear each other.
* Call timer starts.

---

# FR-089 - Reject Call

## Features

Recipient may reject an incoming call.

---

## Business Rules

* Caller receives "Rejected" status.
* Call record stored in history.

# FR-090 - Missed Call

## Purpose

Handle unanswered calls.

---

## Business Rules

A call becomes **Missed** when:

* Timeout reached.
* Recipient never answered.
* Caller cancelled before answer.

---

## Notifications

Generate:

* In-App Notification
* Optional Email (Configurable)

# FR-095 - Reconnect Call

## Purpose

Recover from temporary network interruptions.

---

## Workflow

1. Connection interrupted.
2. Attempt reconnection.
3. Restore media stream if successful.
4. End call if timeout exceeded.

---

## Business Rules

# FR-099 - Call Security

## Requirements

* HTTPS Required
* Secure WebRTC
* Permission Validation

# Chapter Summary

This chapter defines the complete one-to-one Voice Call Engine for Meet. It includes call initiation, incoming call handling, WebRTC signaling, connection management, call controls, call history, reconnection, quality monitoring, configurable STUN/TURN infrastructure, and secure communication practices. The architecture ensures compatibility with Laravel and cPanel hosting while remaining ready for future infrastructure upgrades.
