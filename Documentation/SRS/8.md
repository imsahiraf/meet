# Software Requirements Specification (SRS)

# Chapter 8 - Video Call Engine

---

# Module Overview

The Video Call Engine extends the Voice Call Engine by adding real-time video communication using WebRTC. The implementation shall remain compatible with Laravel running on standard cPanel hosting by using the polling-based signaling architecture defined in previous chapters.

The backend is responsible only for authentication, authorization, signaling, activity logging, and configuration. Audio and video streams must flow directly between participants through WebRTC whenever possible.

---

# FR-101 - Start Video Call

## Purpose

Allow an authenticated user to initiate a one-to-one video call.

---

## Actor

Authenticated User

---

## Priority

Critical

---

## Preconditions

* Caller is authenticated.
* Recipient account is active.
* Camera permission available.
* Microphone permission available.
* Recipient is available for calls.

---

## Workflow

1. User opens a conversation.
2. User clicks **Video Call**.
3. Browser requests camera and microphone permissions.
4. WebRTC Peer Connection is created.
5. SDP Offer generated.
6. Offer sent to Laravel signaling API.
7. Recipient receives incoming video call notification.
8. Recipient accepts or rejects the call.

---

## Database Tables

* calls
* call_participants
* signaling_messages
* activity_logs

---

## Acceptance Criteria

* Video call invitation delivered.
* Camera preview starts.
* Connection established after acceptance.

# Chapter Summary

The Video Call Engine provides secure one-to-one video communication using WebRTC with Laravel-based signaling. It includes camera and microphone management, adaptive quality, screen sharing, device selection, reconnection handling, lifecycle management, and future-ready extensibility. The backend remains responsible only for signaling, configuration, logging, and authorization, while media flows directly between participants whenever peer-to-peer connectivity is established.
