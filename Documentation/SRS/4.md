# Software Requirements Specification (SRS)

# Chapter 4 - Chat Engine

---

# Module Overview

The Chat Engine is the core communication module of the Meet platform. It shall provide secure, fast, scalable one-to-one and group messaging while remaining compatible with Laravel running on standard cPanel hosting.

The module shall use an optimized polling architecture for real-time updates. Future WebSocket support must be architecturally possible without requiring major changes.

---

# FR-036 - Start Conversation

## Purpose

Allow an authenticated user to initiate a private conversation with another registered user.

### Actor

Authenticated User

### Preconditions

* Both users have active accounts.
* Recipient has not blocked the sender.
* Sender has permission to message the recipient.

### Workflow

1. User selects a contact.
2. User clicks **Message**.
3. System checks whether a conversation already exists.
4. If not, a new conversation is created.
5. Chat window opens.

### Database Tables

* conversations
* conversation_participants

### Acceptance Criteria

* Existing conversation opens if available.
* Otherwise, a new conversation is created successfully.

# FR-037 - Send Text Message

## Purpose

Allow users to exchange text messages.

### Features

* UTF-8 support
* Emoji support
* Unlimited line breaks
* URL detection
* Mention-ready architecture
* Rich text reserved for future versions

### Validation Rules

* Empty messages are not allowed.
* Maximum message length is configurable.
* HTML input must be sanitized.

### Database Tables

* messages
* message_status

### Acceptance Criteria

* Message is stored successfully.
* Recipient receives the message through the polling engine.
* Delivery status is updated.

# FR-053 - Chat Polling Engine

## Purpose

Provide near real-time message synchronization without WebSockets.

### Architecture

* Open Conversation: configurable polling interval (default 700-1000 ms)
* Conversation List: configurable polling interval (default 5-10 seconds)
* Notifications: configurable polling interval (default 3 seconds)

### Business Rules

* Polling intervals must be configurable through the Admin Panel.
* Requests should only return incremental changes since the last successful synchronization.
