# 3. Foreign Key Standards

All foreign keys shall:

* Reference primary keys only.
* Be indexed.
* Use Laravel migration constraints.
* Prevent orphan records.
* Follow consistent naming.

Example:

```text
user_id

meeting_id

conversation_id

message_id

group_id

media_id
```

# 5. Primary Key Strategy

Every table shall contain

```text
id
```

Type

```text
BIGINT UNSIGNED AUTO_INCREMENT
```

Every public entity shall also contain

```text
uuid
```

for public APIs and links.

---

# 6. Timestamp Policy

Transactional tables shall contain

```text
created_at

updated_at
```

Soft delete tables shall additionally contain

```text
deleted_at
```

---

# 7. Soft Delete Policy

Soft Deletes shall be enabled for:

* Users
* Groups
* Meetings
* Messages (where applicable)
* Media Files

Permanent deletion shall follow the configured retention policy.

---

# 8. Index Strategy

Primary Index

```text
PRIMARY KEY(id)
```

Unique Indexes

* uuid
* email
* phone
* meeting_code
* invite_token

Standard Indexes

* status
* created_at
* updated_at
* user_id
* conversation_id
* meeting_id
* group_id

Composite indexes shall be added based on common query patterns.

# 11. Transaction Guidelines

Database transactions shall be used for:

* User Registration
* Meeting Creation
* Group Creation
* Contact Acceptance
* File Upload Completion
* Archive Generation
* Permission Updates

Operations involving multiple related writes must be atomic.

---

# 12. Performance Guidelines

* Use eager loading to reduce N+1 queries.
* Paginate large result sets.
* Select only required columns.
* Archive historical data according to retention policies.
* Optimize frequently executed queries.

---

# 13. Storage Strategy

Database stores metadata only.

Binary files are stored on disk.

Each media record references:

* Storage Path
* File Name
* MIME Type
* File Size
* Owner
* Related Module

Storage implementation shall remain replaceable.

---

# 14. Scheduler Responsibilities

Laravel Scheduler shall manage:

* Expired OTP cleanup
* Expired password reset tokens
* Upload cleanup
* One View cleanup
* Notification retries
* Archive generation
* Backup scheduling
* Log cleanup
* Report generation
* Meeting reminders

---

# 15. Queue Responsibilities

Queues shall process:

* Email delivery
* Meeting invitations
* Calendar (.ics) generation
* Notification dispatch
* Thumbnail generation
* Archive generation
* Backup creation
* Report exports

Queue driver shall be configurable.

---

# 16. Security Guidelines

* Hash passwords using Laravel defaults.
* Never store plaintext passwords.
* Encrypt sensitive configuration values.
* Rate-limit authentication endpoints.
* Log security-sensitive operations.
* Validate all user input.
* Enforce authorization through policies.

---

# 17. Backup Strategy

Support:

* Manual backups
* Scheduled backups
* Database backups
* File backups
* Full system backups

Backup retention shall be configurable.

---

# 18. Restore Strategy

Support:

* Database restore
* File restore
* Full restore

Restore operations shall be logged.

---

# 19. Archive Strategy

Support archiving for:

* Chat history
* Meeting history
* Audit logs
* Reports
* Files

Retention periods shall be configurable.

---

# 20. Database Growth Strategy

Designed to scale from:

* 100 users
* 1,000 users
* 10,000 users
* 100,000 users
* 1,000,000+ users

without requiring schema redesign.

---

# 21. Development Rules

Developers shall:

* Use Laravel Migrations.
* Use Eloquent Models.
* Use Form Requests for validation.
* Use Services for business logic.
* Use Repositories for data access where adopted.
* Use Events and Queued Jobs for asynchronous work.
* Follow the documented relationships.

Direct database access from controllers is prohibited.

# 24. DDS Completion Summary

The Database Design Specification consists of:

* DDS-1 - Authentication & User Core
* DDS-2 - Contacts & Chat Core
* DDS-3 - Groups & Community
* DDS-4 - Voice Calls, Video Calls, Meetings & Whiteboard
* DDS-5 - Media, Files, Calendar & Notifications
* DDS-6 - Administration & Configuration
* DDS-7 - Security, Analytics & Archive
* DDS-8 - Final Database Blueprint

Together these documents define the complete logical database design for the Meet platform, covering approximately 100 production-oriented tables and their relationships. They provide the implementation blueprint for Laravel migrations, Eloquent models, services, APIs, and future enhancements while remaining compatible with deployment on a cPanel-hosted Laravel application.
