# TABLE 6

# trusted_devices

---

## Purpose

Stores user-approved devices that can access the account without requiring repeated verification (subject to security policies).

---

## Table Name

```text
trusted_devices
```

---

## Columns

| Column            | Data Type       | Length | Null | Default           | Index   |
| ----------------- | --------------- | ------ | ---- | ----------------- | ------- |
| id                | BIGINT UNSIGNED | -      | No   | Auto Increment    | Primary |
| uuid              | CHAR            | 36     | No   | Generated         | Unique  |
| user_id           | BIGINT UNSIGNED | -      | No   | -                 | Index   |
| device_identifier | VARCHAR         | 255    | No   | -                 | Unique  |
| device_name       | VARCHAR         | 150    | Yes  | NULL              | -       |
| browser           | VARCHAR         | 100    | Yes  | NULL              | -       |
| operating_system  | VARCHAR         | 100    | Yes  | NULL              | -       |
| platform          | VARCHAR         | 50     | Yes  | NULL              | -       |
| last_used_at      | TIMESTAMP       | -      | Yes  | NULL              | Index   |
| trusted_at        | TIMESTAMP       | -      | No   | CURRENT_TIMESTAMP | -       |
| status            | ENUM            | -      | No   | active            | Index   |
| created_at        | TIMESTAMP       | -      | No   | CURRENT_TIMESTAMP | -       |
| updated_at        | TIMESTAMP       | -      | No   | CURRENT_TIMESTAMP | -       |

---

## Status Values

* active
* revoked
* expired

---

## Business Rules

* Users may revoke trusted devices.
* Administrators may revoke trusted devices.
* Trust duration shall be configurable.
* Revoked devices cannot bypass future verification.

---

## Relationships

User

↓

Many Trusted Devices

---

## Laravel Model

```text
App\Models\TrustedDevice
```

# TABLE 7

# login_attempts

---

## Purpose

Records successful and failed login attempts for security monitoring, rate limiting, and auditing.

---

## Table Name

```text
login_attempts
```

---

## Columns

| Column         | Data Type       | Length | Null | Default           | Index   |
| -------------- | --------------- | ------ | ---- | ----------------- | ------- |
| id             | BIGINT UNSIGNED | -      | No   | Auto Increment    | Primary |
| uuid           | CHAR            | 36     | No   | Generated         | Unique  |
| user_id        | BIGINT UNSIGNED | Yes    | NULL | Index             |         |
| email          | VARCHAR         | 255    | Yes  | NULL              | Index   |
| phone          | VARCHAR         | 20     | Yes  | NULL              | Index   |
| ip_address     | VARCHAR         | 45     | Yes  | NULL              | Index   |
| user_agent     | TEXT            | -      | Yes  | NULL              | -       |
| login_result   | ENUM            | -      | No   | failed            | Index   |
| failure_reason | VARCHAR         | 255    | Yes  | NULL              | -       |
| attempted_at   | TIMESTAMP       | -      | No   | CURRENT_TIMESTAMP | Index   |
| created_at     | TIMESTAMP       | -      | No   | CURRENT_TIMESTAMP | -       |
| updated_at     | TIMESTAMP       | -      | No   | CURRENT_TIMESTAMP | -       |

---

## Login Results

* success
* failed
* blocked

---

## Business Rules

* Every login attempt shall be recorded.
* Failed attempts contribute to account lockout policies.
* Administrators may review login history.

---

## Relationships

User

↓

Many Login Attempts

---

## Laravel Model

```text

```

---

* online
* offline
* away
* busy
* invisible

---

* Presence updates should be lightweight to minimize database load.

# DDS-1 Status

The Authentication & User Core module is now fully defined. It establishes the identity, authentication, session management, device management, profile, preferences, privacy, and presence foundation for the Meet platform. All subsequent database modules (Contacts, Chat, Groups, Meetings, Files, Notifications, and Administration) will reference this module through foreign key relationships.
