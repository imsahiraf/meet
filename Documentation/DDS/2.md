# Module Overview

The Contacts & Chat Core Module manages user relationships, conversations, messaging, delivery tracking, reactions, read receipts, typing indicators, pinned chats, starred messages, drafts, and chat-specific settings.

This module integrates with:

* Authentication
* User Profile
* Media & Files
* Voice Calls
* Video Calls
* Meetings
* Notifications
* Analytics
* Archive

Every chat feature shall use these tables as the primary source of truth.

# TABLE 1

# contacts

---

## Purpose

Stores approved contact relationships between registered users.

Unlike a phone address book, this table represents relationships within the Meet platform.

---

## Table Name

```text
contacts
```

---

## Columns

| Column          | Type            | Null | Default           |
| --------------- | --------------- | ---- | ----------------- |
| id              | BIGINT UNSIGNED | No   | Auto Increment    |
| uuid            | CHAR(36)        | No   | Generated         |
| user_id         | BIGINT UNSIGNED | No   | -                 |
| contact_user_id | BIGINT UNSIGNED | No   | -                 |
| nickname        | VARCHAR(100)    | Yes  | NULL              |
| is_favorite     | BOOLEAN         | No   | false             |
| created_at      | TIMESTAMP       | No   | CURRENT_TIMESTAMP |
| updated_at      | TIMESTAMP       | No   | CURRENT_TIMESTAMP |

---

## Foreign Keys

* user_id → users.id
* contact_user_id → users.id

---

## Business Rules

* Duplicate contacts are not allowed.
* A user cannot add themselves as a contact.
* Nicknames are optional.
* Contact relationships are independent; if mutual acceptance is required, it is handled through `contact_requests`.

---

## Indexes

* UNIQUE(user_id, contact_user_id)
* INDEX(user_id)
* INDEX(contact_user_id)

---

## Relationships

User

↓

Many Contacts

---

# TABLE 2

# contact_requests

---

## Purpose

Stores pending, accepted, rejected, or cancelled contact requests.

---

## Columns

| Column       | Type                                      |
| ------------ | ----------------------------------------- |
| id           | BIGINT UNSIGNED                           |
| uuid         | CHAR(36)                                  |
| sender_id    | BIGINT UNSIGNED                           |
| receiver_id  | BIGINT UNSIGNED                           |
| status       | ENUM(pending,accepted,rejected,cancelled) |
| message      | VARCHAR(255) NULL                         |
| responded_at | TIMESTAMP NULL                            |
| created_at   | TIMESTAMP                                 |
| updated_at   | TIMESTAMP                                 |

---

## Business Rules

* Only one pending request between the same users.
* Accepted requests automatically create records in `contacts`.
* Rejected or cancelled requests remain for audit until retention cleanup.

---

# TABLE 3

# blocked_users

---

## Purpose

Stores users blocked by another user.

---

## Columns

* id
* uuid
* user_id
* blocked_user_id
* reason (optional)
* created_at
* updated_at

---

## Business Rules

When a user is blocked:

* Private messages are not delivered.
* Voice calls are not allowed.
* Video calls are not allowed.
* Contact requests are rejected automatically.
* Meeting invitations may be restricted according to meeting settings.

---

# TABLE 4

# favorite_contacts

---

## Purpose

Stores favorite contacts for quick access.

---

## Columns

* id
* uuid
* user_id
* contact_user_id
* sort_order
* created_at
* updated_at

---

## Business Rules

* Favorites affect only the owner's interface.
* A contact may be marked as favorite only once.

---

# TABLE 5

# conversations

---

## Purpose

Represents every private or group conversation.

This table is the parent entity for all chat messages.

---

## Columns

| Column           | Type                        |
| ---------------- | --------------------------- |
| id               | BIGINT UNSIGNED             |
| uuid             | CHAR(36)                    |
| type             | ENUM(private,group,meeting) |
| title            | VARCHAR(255) NULL           |
| last_message_id  | BIGINT NULL                 |
| last_activity_at | TIMESTAMP                   |
| is_archived      | BOOLEAN                     |
| created_by       | BIGINT                      |
| created_at       | TIMESTAMP                   |
| updated_at       | TIMESTAMP                   |

---

## Business Rules

* Private conversations contain exactly two members.
* Group conversations are linked to the Groups module.
* Meeting conversations are linked to the Meetings module.

---

## Relationships

Conversation

↓

Many Messages

Conversation

↓

Many Members

---

# TABLE 6

# conversation_members

---

## Purpose

Maps users to conversations.

---

## Columns

* id
* uuid
* conversation_id
* user_id
* joined_at
* left_at
* role
* is_muted
* is_archived
* created_at
* updated_at

---

## Business Rules

* One active membership per conversation.
* Members may archive a conversation independently.

---

# TABLE 7

# messages

---

## Purpose

Stores every chat message exchanged through the platform.

---

## Supported Message Types

* text
* image
* video
* audio
* file
* location
* contact
* system
* one_view

---

## Columns

| Column              | Type                                      |
| ------------------- | ----------------------------------------- |
| id                  | BIGINT UNSIGNED                           |
| uuid                | CHAR(36)                                  |
| conversation_id     | BIGINT                                    |
| sender_id           | BIGINT                                    |
| reply_to_message_id | BIGINT NULL                               |
| message_type        | ENUM                                      |
| body                | LONGTEXT NULL                             |
| media_id            | BIGINT NULL                               |
| status              | ENUM(sending,sent,delivered,read,deleted) |
| edited_at           | TIMESTAMP NULL                            |
| deleted_at          | TIMESTAMP NULL                            |
| created_at          | TIMESTAMP                                 |
| updated_at          | TIMESTAMP                                 |

---

## Business Rules

* Every message belongs to one conversation.
* One View media references the Media module.
* Deleted messages follow the retention policy.
