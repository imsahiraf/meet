# Meet v1.0

# Claude Development Manual (CDM)

## CDM - Part 4

## AI Coding Standards & Decision Framework

**Version:** 1.0

**Target AI:** Claude (Latest Version)

**Framework:** Laravel 12

---

# 1. Purpose

This document defines the decision-making framework, coding standards, quality expectations, regeneration strategy, and operational rules that the AI shall follow while generating or modifying code for the Meet platform.

The objective is to ensure predictable, maintainable, and production-ready output across the entire project.

---

# 2. AI Decision Principles

When multiple valid approaches exist, the AI shall prioritize:

* Simplicity
* Maintainability
* Security
* Performance
* Readability
* Framework Conventions
* Long-Term Scalability

Short-term implementation convenience shall not override architectural consistency.

---

# 3. Documentation Hierarchy

The AI shall consult project documentation in the following order:

1. Software Requirements Specification (SRS)
2. Database Design Specification (DDS)
3. REST API Specification (RAS)
4. UI/UX Design System (UDS)
5. Laravel Development Guide (LDG)
6. Claude Development Manual (CDM)

If a conflict exists, the AI shall identify it explicitly before proposing a resolution.

---

# 4. Code Generation Rules

Generated code shall:

* Compile successfully.
* Follow Laravel conventions.
* Avoid duplicated logic.
* Prefer reusable components.
* Include meaningful names.
* Maintain consistent formatting.

Generated code shall not intentionally leave placeholder logic for required functionality.

---

# 5. Architecture Compliance

The AI shall preserve:

* Controller Layer
* Service Layer
* Repository Layer
* Policy Layer
* Resource Layer
* Event Layer
* Queue Layer

Business rules shall remain in the Service Layer unless a documented exception applies.

---

# 6. Refactoring Rules

When improving existing code, the AI shall:

* Preserve external behavior.
* Improve readability.
* Reduce duplication.
* Maintain compatibility.
* Update related documentation where necessary.

Refactoring shall not introduce unnecessary architectural changes.

---

# 7. Error Recovery Strategy

When generation encounters incomplete requirements, the AI shall:

* Identify missing information.
* Explain the dependency.
* Avoid unsupported assumptions.
* Continue with unaffected sections where possible.

The AI shall distinguish between documented facts and inferred recommendations.

---

# 8. Conflict Resolution

If two documents appear inconsistent, the AI shall:

* Identify both sources.
* Describe the inconsistency.
* Recommend the least disruptive resolution.
* Request clarification when the impact is significant.

The AI shall not silently choose one interpretation.

---

# 9. Documentation Rules

Every generated feature shall include:

* Technical Notes
* Configuration Requirements
* Testing Notes
* Operational Considerations

Documentation shall reflect the implemented solution rather than aspirational behavior.

---

# 10. Security Decision Rules

The AI shall always:

* Validate input.
* Enforce authorization.
* Protect sensitive data.
* Use secure defaults.
* Follow the principle of least privilege.

Security considerations shall be addressed before optimization.

---

# 11. Performance Decision Rules

The AI shall:

* Avoid N+1 queries.
* Use eager loading appropriately.
* Queue long-running tasks.
* Paginate large datasets.
* Optimize expensive operations.

Performance optimizations shall not reduce correctness.

---

# 12. Testing Requirements

Generated implementations shall include:

* Unit Tests
* Feature Tests
* Authorization Tests
* Validation Tests

Additional integration tests shall be added for complex workflows.

---

# 13. Code Review Checklist

Before considering generated code complete, verify:

* Correctness
* Security
* Performance
* Readability
* Test Coverage
* Documentation
* Architecture Compliance

The AI shall identify any unmet review criteria.

---

# 14. Regeneration Strategy

If regeneration is requested, the AI shall:

* Preserve compatible interfaces.
* Avoid duplicate implementations.
* Reuse existing modules.
* Explain breaking changes before introducing them.

Regeneration shall minimize disruption to completed work.

---

# 15. Unsupported Requests

If a request conflicts with documented project architecture, the AI shall:

* Explain the conflict.
* Recommend a compliant alternative.
* Preserve the established architecture unless explicitly instructed to redesign it.

---

# 16. AI Limitations

The AI shall acknowledge when:

* Requirements are incomplete.
* External systems are unspecified.
* Design decisions require user input.
* Documentation contains ambiguity.

Transparency is preferred over unsupported certainty.

---

# 17. Completion Criteria

Generated work shall be considered complete only when:

* Code generated
* Validation implemented
* Authorization enforced
* Tests prepared
* Documentation updated
* Architecture preserved

Completion status shall accurately reflect outstanding work.

---

# 18. Long-Term Maintainability

Generated code shall support:

* Future Laravel upgrades
* Additional modules
* Performance improvements
* Cloud deployments
* Enterprise customization

Maintainability shall guide implementation decisions.

---

# 19. Final Quality Gates

Before finalizing any module, confirm:

* Functional correctness
* Security compliance
* Performance considerations
* Documentation completeness
* Testing readiness
* Coding standard compliance

Quality gates apply to every generated feature.

---

# 20. Future Expansion

The AI decision framework supports future capabilities including:

* Multi-AI Development Workflows
* Automated Code Review
* Static Analysis Integration
* Security Scanning
* Architectural Validation
* Plugin Generation

Future enhancements shall integrate into the existing governance model.

---

# CDM-4 Summary

This document establishes the AI decision framework for the Meet platform, defining coding standards, architectural compliance, refactoring rules, conflict resolution, security and performance decision-making, testing expectations, quality gates, and long-term maintainability requirements for AI-assisted development.
