# Meet v1.0

# Claude Development Manual (CDM)

## CDM - Part 1

## Master Development Prompt & AI Development Principles

**Version:** 1.0

**Target AI:** Claude (Latest Version)

**Backend:** Laravel 12

**Frontend:** Blade + Bootstrap 5 + Vanilla JavaScript

**Database:** MySQL 8+

---

# 1. Purpose

This document defines the master instructions for AI-assisted development of the Meet platform.

Its objective is to ensure that every generated file, module, feature, and implementation follows the project's architecture, coding standards, documentation, and quality requirements.

The AI shall treat all previous project documentation as authoritative.

---

# 2. Primary Objective

The AI shall generate a complete, production-ready Meet platform that is:

* Modular
* Secure
* Scalable
* Maintainable
* Testable
* Responsive
* Fully Documented

Generated code shall be suitable for deployment after validation and testing.

---

# 3. AI Development Principles

The AI shall prioritize:

* Correctness
* Maintainability
* Readability
* Security
* Performance
* Consistency
* Simplicity

Architectural consistency takes precedence over generating the shortest possible code.

---

# 4. Project Context

The AI shall assume:

Framework

* Laravel 12

Frontend

* Blade
* Bootstrap 5
* Vanilla JavaScript

Authentication

* Laravel Sanctum

Database

* MySQL 8+

Deployment

* Apache
* cPanel
* Linux

---

# 5. Documentation Priority

When generating code, the AI shall follow documents in this order:

1. Software Requirements Specification (SRS)
2. Database Design Specification (DDS)
3. REST API Specification (RAS)
4. UI/UX Design System (UDS)
5. Laravel Development Guide (LDG)

If documentation appears inconsistent, the AI shall identify the conflict and request clarification rather than making unsupported assumptions.

---

# 6. AI Responsibilities

The AI shall:

* Generate production-quality code.
* Follow Laravel conventions.
* Reuse existing modules.
* Avoid duplicate implementations.
* Generate tests where applicable.
* Produce maintainable code.

The AI shall not intentionally bypass project standards for convenience.

---

# 7. Architectural Rules

Generated code shall use:

* Controllers
* Services
* Repositories
* Policies
* Form Requests
* Resources
* Events
* Listeners
* Queue Jobs

Business logic shall reside in the Service Layer.

---

# 8. Coding Standards

Generated code shall comply with:

* PSR-12
* Laravel Best Practices
* SOLID Principles
* DRY
* KISS

Readable code is preferred over unnecessarily clever implementations.

---

# 9. Database Rules

The AI shall:

* Use existing migrations.
* Reuse existing models.
* Respect relationships.
* Avoid schema duplication.

Database modifications shall remain consistent with the DDS.

---

# 10. API Rules

The AI shall:

* Follow REST conventions.
* Use API Resources.
* Return standardized responses.
* Respect authentication and authorization.

The REST API Specification is the authoritative API contract.

---

# 11. UI Rules

The AI shall:

* Follow the UI/UX Design System.
* Reuse existing components.
* Maintain responsive behavior.
* Preserve accessibility.

Visual consistency shall be maintained across modules.

---

# 12. Security Rules

The AI shall:

* Validate input.
* Authorize protected actions.
* Hash passwords.
* Protect uploaded files.
* Avoid exposing sensitive information.

Security-sensitive features shall include appropriate safeguards.

---

# 13. Performance Rules

Generated code shall:

* Use eager loading where appropriate.
* Paginate large datasets.
* Queue long-running tasks.
* Avoid N+1 queries.

Performance considerations shall be included during implementation.

---

# 14. Testing Requirements

Generated features shall include:

* Unit Tests
* Feature Tests
* Validation Tests
* Authorization Tests

Tests shall reflect the implemented business requirements.

---

# 15. Documentation Requirements

For each implemented feature, the AI shall generate:

* Implementation Notes
* Configuration Notes
* Testing Notes

Documentation shall remain synchronized with generated code.

---

# 16. Error Handling

Generated code shall:

* Throw meaningful exceptions.
* Return standardized error responses.
* Log operationally significant failures.

Internal implementation details shall not be exposed to end users.

---

# 17. Code Generation Strategy

Each generated feature shall include:

1. Migration (if required)
2. Model
3. Repository
4. Service
5. Policy
6. Form Request
7. Controller
8. Resource
9. Event
10. Listener
11. Queue Job (if applicable)
12. Tests

The AI shall identify when individual elements are not required rather than generating unnecessary files.

---

# 18. Quality Checklist

Before considering a generated module complete, verify:

* Architecture Compliance
* Security
* Validation
* Authorization
* Testing
* Documentation
* Performance

The AI shall identify outstanding work if any checklist items remain incomplete.

---

# 19. Future Compatibility

Generated code shall be structured to accommodate:

* Additional Modules
* New APIs
* Cloud Storage
* Redis
* WebSockets
* Future Laravel Versions

Future extensibility shall be considered during implementation.

---

# 20. CDM-1 Summary

This document establishes the master operating instructions for AI-assisted development of the Meet platform. It defines project priorities, architectural expectations, implementation standards, quality requirements, and documentation hierarchy to ensure that generated code remains consistent with the overall system design.
