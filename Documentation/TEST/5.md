# Meet v1.0

# Test Case & QA Manual (TEST)

## TEST - Part 5

## Voice & Video Calling Test Cases

**Version:** 1.0

**Module:** Voice & Video Calling

**Priority:** Critical

---

# 1. Purpose

This document defines the functional, real-time, security, performance, API, and recovery test cases for the Voice and Video Calling modules.

The objective is to ensure reliable, secure, and high-quality communication across supported devices and network conditions.

---

# 2. Test Coverage

The following functionality shall be validated:

* Voice Calls
* Video Calls
* Incoming Calls
* Outgoing Calls
* Screen Sharing
* Device Management
* Call Recovery
* Call History
* Notifications
* WebRTC Connectivity

---

# 3. Voice Call Test Cases

| Test ID  | Test Case            | Expected Result                |
| -------- | -------------------- | ------------------------------ |
| CALL-001 | Start voice call     | Call initiated successfully    |
| CALL-002 | Accept incoming call | Voice session established      |
| CALL-003 | Reject incoming call | Call terminated correctly      |
| CALL-004 | End active call      | Call ends and history recorded |
| CALL-005 | Miss incoming call   | Missed call logged             |

---

# 4. Video Call Test Cases

| Test ID  | Test Case                               | Expected Result            |
| -------- | --------------------------------------- | -------------------------- |
| CALL-101 | Start video call                        | Video session established  |
| CALL-102 | Enable/Disable camera                   | Camera state updated       |
| CALL-103 | Switch camera (supported devices)       | Active camera changed      |
| CALL-104 | Full-screen mode                        | Video expands correctly    |
| CALL-105 | Picture-in-Picture (supported browsers) | PiP activated successfully |

---

# 5. Screen Sharing Tests

Validate:

* Start Screen Sharing
* Stop Screen Sharing
* Share Browser Tab
* Share Application Window
* Share Entire Screen
* Permission Denied Handling

Screen sharing shall terminate immediately when permission is revoked.

---

# 6. Device Management Tests

Validate:

* Camera Selection
* Microphone Selection
* Speaker Selection (where supported)
* Device Preview
* Device Change During Call

Selected devices shall function correctly after switching.

---

# 7. WebRTC Connectivity Tests

Verify:

* STUN Connectivity
* TURN Relay Connectivity
* ICE Candidate Exchange
* Peer Connection Establishment
* Media Stream Negotiation

Connection establishment shall remain reliable under supported environments.

---

# 8. Call Recovery Tests

Validate:

* Temporary Network Loss
* Reconnection Attempt
* Call Resume
* Connection Timeout
* Call Failure Handling

Recovery behavior shall remain predictable and user-friendly.

---

# 9. Call History Tests

Verify:

* Outgoing Call Record
* Incoming Call Record
* Missed Call Record
* Call Duration
* Call Status Accuracy

History shall accurately reflect completed call activity.

---

# 10. API Test Cases

Endpoints shall verify:

### Voice

* Start Call
* Accept Call
* Reject Call
* End Call

### Video

* Start Video Call
* Accept Video Call
* Reject Video Call
* End Video Call

### General

* Retrieve Call History
* Update Device Preferences

API responses shall comply with the REST API Specification (RAS).

---

# 11. Security Tests

Validate:

* Authentication
* Authorization
* Contact Validation
* Secure Signaling
* Rate Limiting
* Session Validation

Unauthorized users shall not initiate or join protected call sessions.

---

# 12. Negative Test Cases

Verify:

* Call blocked user
* Accept expired call request
* Join unauthorized session
* Invalid signaling payload
* Disconnect during negotiation
* Device unavailable

The system shall fail securely and recover gracefully where possible.

---

# 13. Performance Tests

Measure:

* Call Setup Time
* Audio Latency
* Video Stability
* Screen Sharing Startup
* Reconnection Time

Performance shall satisfy the Non-Functional Requirements (NFR).

---

# 14. Regression Tests

Regression testing shall verify:

* Voice Calls
* Video Calls
* Screen Sharing
* Device Management
* Call History
* Notifications
* WebRTC Connectivity

Previously resolved issues shall remain resolved.

---

# 15. Acceptance Criteria

The module is accepted only when:

* Voice calls operate reliably.
* Video calls operate reliably.
* Screen sharing functions correctly.
* Device management is stable.
* Call recovery behaves correctly.
* Documentation is synchronized.
* No critical defects remain.

---

# 16. TEST-5 Summary

This document defines the complete QA validation framework for the Voice and Video Calling modules, including WebRTC validation, device management, screen sharing, recovery testing, API verification, security testing, performance testing, regression testing, and acceptance criteria.
